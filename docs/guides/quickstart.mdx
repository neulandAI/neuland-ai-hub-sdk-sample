The API authenticates every request with an **API key** sent in the
`X-API-KEY` header:

```
X-API-KEY: ak_prod_v1.<key_id>.<secret>
```

## Create an API key

Keys are created in the Hub web app. Every user can create keys for their own
account; admins can also manage other users' keys.

<Steps>
  <Step title="Sign in to the Hub">
    Use your normal Hub login.
  </Step>
  <Step title="Open Settings, then API Keys">
    Click your profile, choose **Settings**, then **API Keys** in the left menu.
  </Step>
  <Step title="Create the key">
    Click **Create API Key**, enter an **API Key Name** you will recognise
    later, for example `Production API`, and confirm.
  </Step>
  <Step title="Copy and store it">
    Click **Copy Key**. The full key is shown **once**. Store it in a password
    manager or your secrets manager. It cannot be retrieved again; if you lose
    it, revoke it and create a new one.
  </Step>
</Steps>

<Note>
  Don't see **API Keys** under Settings? Key creation is switched on per Hub
  deployment, and your account needs the "create own API key" permission. Ask
  your Hub admin.
</Note>

<Accordion title="Advanced: create a key from a script">
  The same action is available as `POST /api/key/`. It only works from a
  signed-in session: log in with your Hub email and password to get a bearer
  token, then create the key with it. An API key cannot create or revoke API
  keys, and accounts that sign in through SSO have no password to use here, so
  for most people the web app above is the way.

  <CodeGroup>

  ```bash curl
  TOKEN=$(curl -sS -X POST https://api.your-domain.com/auth/token \
    -d "username=you@example.com" -d "password=<your password>" -d "grant_type=password" \
    | python3 -c "import json,sys; print(json.load(sys.stdin)['access_token'])")

  curl -X POST https://api.your-domain.com/api/key/ \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"name": "ci-pipeline", "description": "Used by the CI deploy job"}'
  ```

  ```python Python
  import neuland_hub_sdk
  from neuland_hub_sdk.api.api_key import ApiKey
  from neuland_hub_sdk.api.auth import Auth
  from neuland_hub_sdk.models.api_key_create_request import ApiKeyCreateRequest

  configuration = neuland_hub_sdk.Configuration(host="https://api.your-domain.com")

  with neuland_hub_sdk.ApiClient(configuration) as api_client:
      token = Auth(api_client).auth_login(
          username="you@example.com", password="<your password>", grant_type="password"
      )
      configuration.access_token = token.access_token

      created = ApiKey(api_client).api_create_key(
          api_key_create_request=ApiKeyCreateRequest(
              name="ci-pipeline",
              description="Used by the CI deploy job",
          ),
      )
      print(created.key)  # full secret — shown once
  ```

  ```typescript TypeScript
  import { Configuration, Auth, ApiKey } from "@neulandai/neuland-hub-sdk";

  const configuration = new Configuration({ basePath: "https://api.your-domain.com" });

  // authLogin(username, password, ...headers, sessionId, grantType)
  const { data: token } = await new Auth(configuration).authLogin(
    "you@example.com", "<your password>",
    undefined, undefined, undefined, undefined, undefined, "password",
  );
  configuration.accessToken = token.access_token;

  // apiCreateKey(cookieName?, apiKeyCreateRequest?) — the body is the 2nd argument.
  const { data } = await new ApiKey(configuration).apiCreateKey(undefined, {
    name: "ci-pipeline",
    description: "Used by the CI deploy job",
  });
  console.log(data.key); // full secret — shown once
  ```

  </CodeGroup>

The response looks like:

```json
{
  "key": "ak_prod_v1.<key_id>.<secret>",
  "key_id": "<key_id>",
  "public_id": "8242077d-c83c-4937-8205-228ff929b26f",
  "expires_at": "2027-01-01T00:00:00Z"
}
```

The full secret (`key`) is shown **once** at creation — store it securely; it
cannot be retrieved again. To rotate or disable a key, revoke it with
`PATCH /api/key/revoke/{public_id}`, again from a signed-in session. The
`public_id` is in the create response and in the key list under **Settings**.
</Accordion>

## Make your first call

Send the key in the `X-API-KEY` header on every request:

```bash
curl https://api.your-domain.com/users/me \
  -H "X-API-KEY: ak_prod_v1.<key_id>.<secret>"
```

<Note>
  Keep API keys secret. Store them in environment variables or a secrets
  manager — never commit them to source control.
</Note>

## Integrated AI applications

AI applications that run **inside** the Neuland AI Hub don't manage their own
API key. Instead, the Hub hands each integrated application a **service token**
(a signed JWT) at invocation. The application reads the API key embedded in that
token and uses it as the `X-API-KEY` on its requests back to the API.

The flow is:

<Steps>
  <Step title="Receive the service token">
    The Hub passes the service token to your application (for example in the
    request headers or environment when your app is launched).
  </Step>
  <Step title="Verify the token and read the API key">
    The token is an RS256 JWT. Verify it with the Hub's RSA public key (ask
    your Hub administrator for it; it is not downloadable from the API), then
    read the API key from the `x-api-key` claim. Both sample backends in this
    repo do exactly that.
  </Step>
  <Step title="Call the API with the extracted key">
    Send the extracted key in the `X-API-KEY` header on every request.
  </Step>
</Steps>

<Warning>
  Treat the extracted API key as a secret: keep it in memory for the duration of
  the request, don't log it, and don't persist it.
</Warning>
