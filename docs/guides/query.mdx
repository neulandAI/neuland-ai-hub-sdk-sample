The Hub exposes a read-only **Query** endpoint that forwards to
[PostgREST](https://postgrest.org). You address a table or view by name and
shape the result with URL parameters: pick columns, filter, sort, paginate, and
embed related rows in one request.

```
GET https://api.your-domain.com/query/<resource>?<postgrest parameters>
GET https://api.your-domain.com/query/rpc/<function>?<parameters>
X-API-KEY: ak_prod_v1.<key_id>.<secret>
```

Ids here are the database columns: `id` and `chat_id` are integers, unlike the
REST endpoints, which take `public_id` UUIDs. Select both when you need to
call a REST method on a row afterwards.

You only ever see the rows your user can see in the Hub. The same row-level
rules apply to the API key as to the browser session, so a key can never read
another user's private chats.

<Note>
  The generated SDK methods `query_query` / `queryQuery` take only the resource
  name. Filters go in the query string, so each example below shows the
  three-line pattern for passing them. Python uses the client's request
  builder; Node passes axios `params`.
</Note>

## Syntax cheat sheet

| Want | Parameter | Example |
|---|---|---|
| Only some columns | `select` | `select=id,name,updated_at` |
| Equals | `<col>=eq.` | `chat_id=eq.42` |
| Greater / less | `gt.` `gte.` `lt.` `lte.` | `created_at=gte.2026-09-01` |
| Pattern, case-insensitive | `ilike.` with `*` | `name=ilike.*meeting*` |
| One of | `in.(…)` | `role=in.(user,assistant)` |
| Boolean / null | `is.` | `already_added=is.false` |
| Sort | `order` | `order=updated_at.desc` |
| Page | `limit`, `offset` | `limit=20&offset=40` |
| Related rows | `relation(cols)` in `select` | `select=id,name,documents(id,filename)` |
| Count related rows | `relation(count)` | `select=id,name,chats(count)` |

Full reference: [PostgREST tables and views](https://postgrest.org/en/stable/references/api/tables_views.html).

Name and last activity, newest first.

<CodeGroup>

```bash curl
curl -H "X-API-KEY: $NLND_HUB_API_KEY" \
  "$HUB/query/chats?select=id,name,updated_at&order=updated_at.desc&limit=10"
```

### Export a chat's history

Every message in chat `42`, oldest first, with the tools each answer called and
the files attached to it. Use `messages_limited`: it hides the model's
intermediate steps and returns one row per visible turn.

<CodeGroup>

```bash curl
curl -H "X-API-KEY: $NLND_HUB_API_KEY" \
  "$HUB/query/messages_limited?select=id,role,content,created_at,tool_calls:tool_calls_limited(id,call_input,call_output,tools(name)),documents:documents_limited(id,filename)&chat_id=eq.42&order=created_at.asc" \
  > chat-42.json
```

### Browse the marketplace (RPC)

`rpc/<function>` calls a database function. This one returns the assistant
marketplace. Filters and sorting work on its output columns like on a table:
top-rated assistants you have not added yet.

<CodeGroup>

```bash curl
curl -H "X-API-KEY: $NLND_HUB_API_KEY" \
  "$HUB/query/rpc/assistant_marketplace_rows?select=name,description,rating_avg,rating_count&already_added=is.false&order=rating_avg.desc.nullslast&limit=10"
```

## Errors

| Status | Meaning | Fix |
|---|---|---|
| `401` | Missing or invalid `X-API-KEY` | Check the key. Revoked keys return 401 too. |
| `400` | PostgREST rejected the query | Usually a typo in `select` or a column that does not exist on that view. The body says which. |
| `404` | Unknown resource | Resource names are lower_snake_case table or view names. |
| `502` | PostgREST unreachable | Transient. Retry. |

Writes are not supported through this endpoint. Use the regular API methods
to create or change data.
